# 持仓分析 Skill (Holdings Analysis Skill)

> 本 skill 沉淀自 2026-05-23 多轮真实持仓复盘对话的经验，专为**港股 / 美股 / A 股 + ETF + 期权组合**的资深散户/半专业投资者设计。
> 适配用户画像：AI 算力链 Alpha 选手 + 复杂期权组合（Covered Call / Bull-Bear Spreads / Credit Spreads）+ 杠杆 ETF（AMUU、2x 海力士）+ A 股主题/ETF轮动。
> **公共规则继承**：本 Skill 继承 `投资分析中枢` 的公共 Hard Rules；若与本文件局部规则冲突，以 `投资分析中枢` 为准。

## 一、调用条件（Trigger Conditions）

**必须立即调用本 skill 的场景**：

1. 用户上传持仓快照（图片 / 表格 / 文本，含正股 + 期权）
2. 用户问 "评估一下我的持仓"、"如何调仓"、"账户健康度"
3. 用户问单笔期权 "是否止损 / 止盈 / Roll out"
4. 用户问 "我应该清仓 X 吗"、"X 还能拿吗"
5. 用户提出过往交易复盘需求
6. 用户对前一轮持仓建议提出反问 / 纠错

**禁止跳过的前置动作**：
- 必须用 `mcp_stock-quant_get_quote` 拉取**所有持仓标的**的实时行情
- 必须用 `mcp_stock-quant_get_signals` 拉取技术指标（RSI / MACD / 布林带 / MA20/50）
- 美股/港股必须用 `mcp_stock-quant_market_env` 获取大盘环境（VIX / SPY / QQQ / SMH / SOXX）
- A 股必须额外拉取核心指数：上证指数 `SH.000001`、深证成指 `SZ.399001`、创业板指 `SZ.399006`、科创50 `SH.000688`；如持仓含 ETF，必须识别 ETF 代码、基金类型、跟踪指数、是否 QDII、是否可能存在溢价/折价风险

### 2. 本 Skill 的接管范围

- ✅ 接管：所有带账户上下文的问题，包括成本、仓位比例、盈亏、保证金、DTE、期权腿。
- ✅ 接管：单笔正股或期权是否止损、止盈、补仓、减仓、Roll out、Roll up/down。

- ❌ 不接管：用户只是问“XXX 公司怎么样/估值贵不贵”，且没有给出持仓信息，转 `个股深度分析`。
- ❌ 不接管：用户只是问“今天美股/A股怎么样”，且没有具体仓位，转对应市场日报 Skill。

### 3. 与其他 Skill 的协同方式

- 与 `个股深度分析`：当持仓决策依赖基本面重估时，引用个股 Skill 的护城河/估值结论，但最终动作由本 Skill 决定。

- 输出时必须说明：“本轮主 Skill = 持仓分析；协同引用 = [如有]”。

## 二、核心方法论：四层分析框架

### Layer 1：方向解读（最易出错，必须二次确认）

| 字段 | 多头（Long） | 空头（Short） |
|------|-------------|--------------|
| 数量 | 正数 | **负数（-1, -2, ...）** |
| 浮盈 | 现价 > 成本 | **现价 < 成本** |
| 浮亏 | 现价 < 成本 | **现价 > 成本** |
| 损失上限 | 成本 × 数量 | 信用价差锁定，裸卖 unlimited |

**Hard Rule**：
- ✅ 看到 `数量 = -1` 必须明确这是**卖出方向**
- ✅ Covered Call (sell call) 浮亏 = 期权价上涨 = 标的上涨 = **正股端获利更多 → 净盈利**
- ❌ 禁止把空头的"浮盈/浮亏"按多头逻辑套用
- ❌ 禁止假设 "60 股 NVDA + 卖 1 张 Call" 是 Naked Short（实际净 Delta 仍为正，**不是裸空**）

### Layer 2：时效性硬门控（持仓附加项，公共部分继承中枢）

> 通用时效校验（now_local / market_phase / data_age / 休市 / overnight 流动性陷阱 / 节假日不出立即操作）统一执行 [投资分析中枢 §2.4 + §2.5](../investment-router/SKILL.md)。本节只保留**持仓决策特有的时效校验**：

| 持仓特有时效项 | 校验内容 |
|---|---|
| 期权 DTE | 距到期天数；< 7 天 + OTM > 5% 进入"Theta 加速区"，必须给止损/Roll 决策 |
| 持仓数据快照时效 | 富途/券商持仓 `update_time` 距离 now_local；> 5min 视为可能错配，必须先刷新 |
| 保证金即时性 | 期权空头/价差需对照实时维持保证金，禁止用昨日数据判断爆仓风险 |
| Roll 截止时点 | 必须显式校验 Roll 操作是否仍在交易时段内（避免落到 closed/holiday 触发 GTC 回退） |
| 财报/FOMC/CPI 临近度 | 持仓含期权时，必须给"事件前 IV crush 概率 + 事件前是否减仓"决策 |
| 当日已成交 vs 挂单 | 持仓里挂单（GTC、stop-loss）必须显式列出，区别于已成交头寸 |

**持仓 Hard Bans**（在中枢公共 Bans 之上叠加）：
- ❌ 禁止把空头方向的浮盈/浮亏按多头逻辑套用（详见 Layer 1）。
- ❌ 禁止在期权到期日当天才提"应该 Roll"，必须在 DTE ≤ 7 天起每天评估。
- ❌ 禁止在保证金触发线 80% 以内不显式提示风险。

#### A 股持仓附加（继承中枢 §2.5 A 股交易制度，本节只列持仓特殊处理）

- A 股持仓出现"涨停一字板"时，必须显式标注"今日不可卖出 / 仅可挂单等待开板"。
- A 股持仓涉及 ETF（QDII / 跨境 / 主题）时，必须给 IOPV vs 场内价差，溢价 > 3% 提示退出风险。
- A 股个股持仓必须纳入 T+1、涨跌停（主板 10%、创业/科创 20%）、停牌、融资融券、政策催化检查。

### Layer 3：单笔仓位评估（期望值 + 时间价值 + 机会成本三件套）

对**每一笔**期权 / 正股，用以下三件套替代直觉：

#### ① 期望值（Expected Value）
```
EV = Σ (情景概率 × 情景损益)
EV > 当前权利金 → 持有
EV < 当前权利金 → 止损（即使浮亏）
```

#### ② 时间价值衰减（Theta）
```
DTE < 7 天 + OTM > 5%      → 止损（Theta 加速接近 100%）
DTE 7-30 天 + OTM 0-5%     → 持有观察
DTE > 60 天                → 时间宽裕，看方向
```

#### ③ 机会成本（Opportunity Cost）
```
止损回收 X 元 vs 持有期望 EV
若 X > EV → 立即止损，资金转投高胜率仓位（如卖 Put 信用价差）
```

### Layer 4：组合层面健康度（6 维度评分卡）

每次复盘必须输出评分卡：

| 维度 | 评分 (1-10) | 评分依据 |
|------|-------------|---------|
| 核心仓选股 | | AI 主线票占比 + 浮盈情况 |
| 持仓纪律 | | 赢家是否拿满 / 输家是否止损 |
| 期权策略复杂度 | | ≤ 6 笔为优，> 10 笔扣分 |
| 风险敞口对冲 | | VIX / Bear Spread / 现金占比 |
| 认知盲区 | | TLT / GLD / 中概互联反复踩坑 |
| 垃圾仓比例 | | -50% 以上仓位占比 |

## 三、强制工作流（每次必走）

### Step 1：调用 MCP 工具拉取实时数据（并发）
```
对所有持仓标的并发调用：
- mcp_stock-quant_get_quote
- mcp_stock-quant_get_signals
对大盘环境调用：
- mcp_stock-quant_market_env
对关键期权调用：
- mcp_stock-quant_calc_greeks（计算 Delta/Theta/Gamma）
```

### Step 2：拆解持仓为 4 类
```
A. AI 算力链多头核心仓（NVDA / GOOGL / META / AMUU / TSEM 等）
B. 相对价值 / Bear Call 对冲（如 ARM 估值过高）
C. 主题股 / 事件驱动股（中概 / 商业航天 / 加密代理）
D. 期权杂项（彩票 lottery / 宏观对冲 / 远月 OTM）
```

**A 股改写为 5 类**：
```
A. 核心盈利趋势仓：已经证明择股有效、仍在 MA20/MA50 上方或基本面强支撑
B. 主题高弹性仓：AI / 芯片 / 卫星 / 科创 / 机器人等，重点看拥挤度与回撤
C. 防御现金流仓：电力、红利、自由现金流 ETF、低估值高股息
D. 弱势亏损仓：跌破 MA20/MA50 且无明确催化，必须有反弹清仓/硬止损计划
E. ETF工具仓：QDII/行业/主题/宽基 ETF，必须检查溢价折价、跟踪指数、成交额
```

### Step 3：单笔评估（每笔输出）
| 字段 | 说明 |
|------|------|
| 标的 | 富途代码 |
| 方向 | 多/空 |
| 数量/成本/现价 | |
| 浮盈/亏（金额 + 百分比） | 注意空头方向反向 |
| 关键技术指标 | RSI / MA / 布林带 |
| DTE（期权专属） | 距到期天数 |
| 期望值 EV | 三段情景估算 |
| **建议动作** | 持有/减仓/止损/Roll |
| **触发条件** | if-then 形式 |

A 股单笔评估必须额外增加：

| 字段 | 说明 |
|------|------|
| 涨跌停制度 | 主板 10%、创业板/科创板 20%、ETF 通常无个股式涨跌停但有流动性/溢价风险 |
| T+1 约束 | 当日买入不可卖出，盘中追高风险更高 |
| 主题拥挤度 | RSI > 70、连续放量、接近 52w 高为拥挤 |
| 估值雷区 | PE_TTM > 100 或利润极低时必须标注"故事股/主题股" |
| ETF 溢价折价 | QDII/跨境 ETF 必查 IOPV/基金公告/溢价风险提示 |
| 政策催化 | 国资、军工、低空、卫星、医药监管、白酒消费政策等 |

### Step 4：组合评分 + 调仓优先级
```
🔴 紧急（24-48h）：风险敞口暴露 / 配比错误 / 加速衰减
🟠 高优（1 周）：胜率低 + 时间不够 + 拖累情绪
🟡 中优（2 周）：等反弹分批清仓
🟢 优化（持续）：赢家加仓 / 信用价差替换
```

### Step 5：永久禁入清单（Lessons Learned）
对反复踩坑的领域写入或调用 project memory 的禁入清单：
- ❌ 长债期权（TLT / TMF）：用户认知盲区，已两次重大亏损
- ❌ 中概互联死扛：小米 -14w / 美团 -3w 教训
- ❌ "故事股"重仓（MSTR / TSLA Robotaxi）：FOMO 模式
- ❌ 远 OTM lottery 期权（OTM > 13% + DTE < 30）
- ❌ Naked Short Call（必须 100 股 / 1 张配比）

## 四、典型场景应对模板

### 场景 A：用户上传持仓截图 + 问"如何评价"

```
1. [拉数据] 并发拉取所有标的 quote + signals + market_env
2. [方向校验] 标注 negative quantity = short，确认浮盈/亏方向正确
3. [时效横幅] 输出 ⏱️ now_et / market_phase / freshness_level / warn
4. [4 类拆解] 按 AI 多头 / 对冲 / 主题 / 期权杂项分组
5. [单笔评估] 每笔给出建议 + 触发条件
6. [评分卡] 6 维度打分
7. [行动清单] 按紧急度 4 档分组
8. [一句话总结] 概括账户病灶（如"主仓优秀，对冲仓拖累"）
```

### 场景 B：用户问"X 应该止损吗"

```
1. [拉实时价] mcp_stock-quant_get_quote(X)
2. [拉技术面] mcp_stock-quant_get_signals(X)
3. [DTE 计算] 如是期权，距到期天数
4. [三件套分析]：
   - 期望值（三段情景概率 × 损益）
   - 时间价值剩余（OTM% vs DTE）
   - 机会成本（止损资金的替代用途）
5. [if-then 决策树]：
   ├── 路径 A：盘前 X 跌至 [价位] 以下 → 持有等到期
   ├── 路径 B：盘前 X 在 [区间] 震荡 → 等开盘 30 分钟方向
   └── 路径 C：盘前 X 跳空 > [价位] → 立即止损
6. [硬止损线] 设置 GTC 单挂出
```

### 场景 C：用户对前一轮建议提出反问 / 纠错

```
1. [立即承认错误] 不要 hedge / defensive
2. [复盘错因] 标注错误模式：
   - 叙事谬误（把过去时翻译成进行时）
   - 数据时效性混淆
   - 沉没成本谬误
   - 直觉判断未经期望值校准
3. [修正决策] 用三件套重新计算
4. [写入 Lessons Learned] 调用 memory 写入项目记忆
5. [感谢用户] 这是模型迭代的核心 signal
```

## 六、持仓本地附加规则（继承中枢 Hard Rules）

> 公共规则（实时数据、禁止训练记忆、MCP 故障、数据源标注、休市校验、决策输出纪律）统一继承 `投资分析中枢`；本节只保留持仓复盘、账户纪律和用户交易偏好的附加规则。

- **沟通**: 中文；高度技术化、结构化（宏观+微观）；表格分解定量分析
- **数据归属**: 所有事实陈述必须带 `_source` 字段（FutuSource / yfinance / StockAnalysis.com）
- **跳过通用 Skill**: 跳过 code-review / debugger / mini-app 等辅助 Skill
- **直接进入数据获取**: 不要重复确认意图，直接调用 MCP 工具
- **拒绝训练记忆推断**: PE / 同比 / TTM 等指标必须从工具拉取，禁止凭记忆给数字
- **量化思维**: 任何"应该 / 建议"前必有期望值估算或概率分布
- **赢家加仓 / 输家斩仓**: 不批评赢家拿不住，但必须批评输家死扛
