# 投资分析中枢 Skill (Investment Router Skill)

> 本 Skill 是所有投资类请求的**统一入口 / 路由中枢 / 公共纪律层**。
> 它不替代专业子 Skill 的深度分析，而是先判断用户问题类型，选择 1 个主路径；只有必要时才组合多个子路径。
> 所有投资子 Skill 必须继承本 Skill 的公共 Hard Rules；若子 Skill 与本 Skill 冲突，**以本 Skill 为准**。

---

## 一、定位与目标

### 1.1 核心目标

把用户所有股票、期权、持仓、市场复盘、IPO、财报、BOM 穿透等投资类问题统一收敛到一个入口：

```
用户问题 → 投资分析中枢 → 路由判断 → 主 Skill → 可选协同 Skill → 可执行输出
```

### 1.2 设计原则

1. **单 Skill 优先**：大多数场景只触发 1 个主 Skill，避免过度分析和重复输出。
2. **持仓优先级最高**：一旦用户给出成本、数量、浮盈亏、期权腿、保证金、Roll 等账户上下文，主路径必须是 `持仓分析`。
3. **市场问题归市场日报**：问大盘、指数、板块、盘前/盘中/盘后时，主路径必须是对应市场日报。
4. **单股研究归个股深度分析**：无持仓上下文的单标的估值、商业模式、护城河、买卖判断，主路径必须是 `个股深度分析`。
5. **公共纪律集中维护**：实时数据、禁止训练记忆、MCP 故障、数据源标注、休市校验等规则集中在本 Skill。
6. **子 Skill 专业化**：子 Skill 只维护其市场/场景的特有规则，不重复定义公共纪律。
7. **可扩展**：新增 `港股IPO投资分析`、`财报专项分析`、`期权策略分析` 等路径时，只需扩展本中枢路由表。

### 1.3 输出第一行强制声明

所有投资类回答第一屏必须声明：

```markdown
> 本轮主路径：<主 Skill>
> 协同路径：<无 / 子 Skill A / 子 Skill B>
> 数据状态：<实时 / 延迟15min / 休市最后交易日 / 数据缺失>
> 时间锚：<now_local, market, market_phase, data_age>
```

示例：

```markdown
> 本轮主路径：个股深度分析
> 协同路径：美股市场每日分析（仅引用 VIX/QQQ/SMH 环境）
> 数据状态：实时 / Futu OpenD
> 时间锚：2026-05-31 10:35 ET, US, regular, data_age < 1min
```

## 二、公共 Hard Rules（所有投资子 Skill 强制继承）

### 2.1 实时数据与数据时效

1. **实时数据强制**：价格、PE、Forward PE、PEG、营收、利润、现金流、目标价、IV、Max Pain、Put-Call Ratio、资金流、换手率、13F 持仓比例、ETF 权重等关键数字，必须当次会话现拉。
2. **禁止训练记忆数字**：不得用模型训练记忆、历史对话、项目记忆中的旧数字充当实时数据。
3. **禁止旧数据伪装实时**：超过 24 小时的数据不得表述为“当前 / 现在 / 实时”；必须标注为历史数据。
4. **数据年龄必填**：所有市场/个股/持仓分析必须输出 `data_age`，例如 `实时`、`延迟15min`、`上一交易日收盘`、`休市前最后快照`。
5. **休市日不出即时操作**：美股/A股/港股休市时，不得输出“今日立即买入/卖出”式指令，只能给 if-then 预案。
6. **同 session 30min 缓存复用规则（v1.3）**：
   - **同一标的、同一会话**内，30 分钟内已拉取的数据可直接复用，不必重复调用 MCP / WebFetch
   - 复用时必须显式注明 `（复用 N 分钟前快照，时间锚 HH:MM ET）`，让用户清楚数据非新鲜拉取
   - **缓存豁免触发条件（强制重拉）**：
     - 距上次拉取 > 30 min
     - 用户明确要求"刷新 / 最新 / 重新拉一下"
     - 出现"盘中关键时点"（开盘 9:30 / 11:30 午休前 / 14:00 收盘前 / 16:00 收盘后 5min / 财报发布后）
     - 标的发生重大事件（财报、监管、停牌、新闻 push）
   - **绝不可缓存的字段**：盘前 / 盘中分时（极速变动）、期权 IV / Greeks（每分钟变化）、订单簿（实时）
   - **可缓存的字段**：基本面（PE / 营收 / 13F / 内部人 / Guidance / 估值百分位）、技术指标快照、催化剂日历

### 2.2 数据源标注

1. **关键数字必须带 `_source`**：例如 `_source=futu`、`_source=yfinance`、`_source=akshare`、`_source=StockAnalysis`、`_source=WebSearch`、`_source=计算`。
2. **计算值必须说明公式**：例如 Upside、Beta、mNAV、估值百分位、EV、最大盈亏、盈亏平衡点。
3. **同一数字多源冲突时必须提示**：若 Futu、yfinance、WebSearch 数字不一致，必须列出差异并以更权威/更实时来源为准。
4. **数据缺失不得补洞**：拿不到的数据必须写 `❌ 数据缺失`，禁止用叙事或常识替代。

### 2.2.X 核心数据禁推断 / 显式标注契约（v1.1）

> 本规则比 §2.2 更严，针对**核心决策数据**（价格 / PE / 营收 / 分部营收 / 毛利率 / EPS / 目标价 / IV / Max Pain / 资金流 / 13F / 内部人 / Guidance / 卖方一致预期）。

1. **禁止自行推断**：核心数据必须**当次会话现拉**或**引用一级源文件**（SEC / 巨潮 / 公司 PR / Futu / yfinance / StockAnalysis / WhaleWisdom / OpenInsider）。**禁止以下行为**：
   - ❌ 凭训练记忆 / 历史对话 / 项目记忆给数字
   - ❌ 用总营收 × 占比反推分部
   - ❌ 用 YoY 反推绝对值
   - ❌ 用同行类比补缺失字段
   - ❌ 用"大约 / 估计 / 预计 / 应该是"等模糊措辞掩盖推断
2. **必要推断必须显式标注**：当且仅当满足"无法实时拉取 + 决策必需"两个条件时允许推断，且**必须四件套全标**：
   - 🟠 **来源标记**：`⚠️ 估算` 或 `⚠️ 推断`
   - 📐 **推断方法**：注明公式或类比依据（如"基于上一季 IR Deck p.X 的 87% 占比 + 当季总营收"）
   - 🎯 **置信度**：`高 / 中 / 低`，推断字段**默认降级为 🟠 三级源**
   - 🔄 **校验路径**：注明等待哪份文件发布后可校验（如"等 SEC 10-Q FY27Q1 发布后校验"）
3. **推断字段禁止单独决策**：标 ⚠️ 的字段不得作为单一决策依据，必须有至少 1 个一级源指标（🟢）共同支持。
4. **报告体检清单**：报告输出前必须自检——所有核心数据要么带 `_source=一级源`，要么带 `⚠️ + 四件套`，无第三种状态。
5. **违规处理**：缺乏标注的推断数字 = §2.8 数据源禁区违规，等同于"包装造假"，下次会话需主动召回并修正。

### 2.3 MCP 故障与降级

当任意 `mcp_stock-quant_*` 工具不可用、返回 `not found` / `list tools failed` / `not available` / 超时 / 空数据时：

1. 必须在回答顶部提示：

```markdown
🚨 实时数据服务异常：stock-quant MCP 当前不可用或返回空数据。
影响：无法确认实时价格/资金流/期权链/技术指标。
处理：请检查 FutuOpenD 与 MCP 配置；在恢复前禁止用缓存或训练记忆伪造实时结论。
```

2. 禁止继续输出伪实时表格。
3. 可以输出“分析框架 / 需补数据清单 / 恢复后执行步骤”，但不得给具体实时交易点位。
4. 若可使用 WebSearch/yfinance/akshare 作为兜底，必须标注其延迟和覆盖范围。

### 2.4 时间锚与市场阶段

所有投资分析必须先确定：

| 字段 | 说明 |
|---|---|
| `now_local` | 对应市场本地时间：ET / 北京时间 / HKT |
| `market` | US / CN / HK / Global / Multi-market |
| `market_phase` | pre-market / regular / after-hours / closed / holiday / morning / lunch-break / afternoon |
| `data_age` | 实时 / 延迟15min / 上一交易日 / 休市前快照 |
| `source_status` | MCP 正常 / MCP 异常 / WebSearch 兜底 / 数据缺失 |

### 2.5 休市日与交易制度

1. **不得仅凭记忆判断休市**：必须用行情返回、交易日历、交易所日历、akshare/yfinance/Futu 状态或可靠 WebSearch 校验。
2. **美股**：区分 pre-market / regular / after-hours / overnight / closed-weekend / closed-holiday。
3. **A 股**：区分集合竞价 / 早盘 / 午休 / 午盘 / 收盘 / 节假日；严格考虑 T+1、涨跌停、停牌、龙虎榜。
4. **港股**：区分早市 / 午休 / 午市 / 收盘 / 半日市；注意南向资金、窝轮/牛熊证、港股通限制。
5. **期权**：必须检查 DTE、到期日、财报日、FOMC/CPI 等 IV crush 事件。

### 2.5.X 盘后 / 隔夜数据时效归属（v1.6）

> **背景**：`after_market` / `overnight` / `pre_market` 字段易被误读为"今日已发生的盘中信号"，实际上其时间归属常常是 **T-1 收盘后到 T 开盘前** 的快照。

1. **强制时间锚标注**：引用 `after_market` / `overnight` / `pre_market` 字段时，必须显式标注归属交易日：
   - ✅ 正确：`盘后 -0.16%（T-1 收盘后 5/29 16:00-20:00 ET）`
   - ❌ 错误：`盘后 -0.16% —— 今日已开始获利了结`
2. **禁止跨日借用**：若 `after_market` 数据时间锚 < T+0 开盘时间，**禁止**作为"今日盘中卖压/买压已开始"的论据。
3. **T+0 盘中信号优先级**：判断"今日是否已开始获利了结/抄底进场"必须基于 **T+0 盘中数据**（intraday RSI / 分时量价 / 资金流 / VWAP 偏离），不得用 T-1 的 after_market / overnight 替代。
4. **隔夜跳空例外**：仅当用于"开盘前预期定价"或"跳空缺口分析"时，T-1 的 after_market 可作为参考，但仍需标注 `（T-1 锚）`。
5. **报告体检**：报告输出前必须自检——所有 `盘后 / 隔夜 / 盘前` 表述要么带 `T-1 / T+0` 时间锚，要么删除。

### 2.6 决策输出纪律

1. **禁止模糊建议**：不得只写“建议关注 / 逢低吸纳 / 谨慎持有 / 可适当配置”。
2. **必须给触发条件**：买入、持有、卖出、止损、止盈、Roll、加仓、减仓必须带 if-then 条件。
3. **必须给具体点位**：若数据可用，必须给价格、均线、支撑、阻力、止损线、目标价或区间。
4. **必须给时间维度**：盘中、未来 1-3 日、未来 2 周、持有 > 2 月、期权 > 3 周等。
5. **必须给失效条件**：判断错误时什么信号出现就退出或重评。
6. **不得 FOMO**：禁止“必须马上买 / 错过就没了 / 无脑冲”等情绪化语言。

### 2.7 投资纪律与用户硬约束

1. **RSI > 75 触发预警**：特别是 CPO、AI 算力链、高 Beta 成长股。
2. **A 股换手率预警**：A 股单日换手率 > 10% 或两日累计约 25%，视为派发/退出风险信号。
3. **CPO 准入规则**：PE > 150 或盈利为负的小盘瓶颈股，仅可作为 < 5% 卫星仓位。
4. **流动性陷阱警示**：小盘/微盘/社交媒体刷屏票必须显式提示冲击成本、退出摩擦和拉高出货风险。
5. **真 Alpha 检验**：必须在 Beta 中性框架下检验，排除单纯市场杠杆暴露。
6. **BOM 穿透优先**：AI 硬件、CPO、HBM、先进封装、机器人供应链等主题，必须优先验证真实供应链位置。

### 2.8 数据源可信度禁区

1. **Finnhub 免费层禁区**：
   - ❌ 禁用：`earnings_history` / `insider` / `economic_calendar` / `price_target` / `upgrade_downgrade` / `social_sentiment`
   - ✅ 可用：`recommendation_trends` / `company_news`
2. **分析师目标价**：StockAnalysis.com / TipRanks / 公司 IR / WebSearch 交叉验证。
3. **内部人交易**：OpenInsider / yfinance insider_transactions / SEC Form 4。
4. **13F 持仓**：WhaleWisdom / Dataroma / SEC 13F / unusualwhales。
5. **A 股公告**：巨潮资讯 / 交易所公告 / akshare / 公司公告。
6. **ETF 持仓**：基金官网 / ETF.com / 交易所披露，不得写死历史权重。

## 三、统一路由矩阵

### 3.1 主路径选择表

| 用户问题类型 | 输入特征 | 主 Skill | 协同 Skill | 触发数量 |
|---|---|---|---|---|
| 美股市场复盘 | “今天美股怎么样 / 盘前 / 盘中 / 盘后 / 标普 / 纳指 / VIX / Mag7 / 半导体” | `美股市场每日分析` | 可选 `个股深度分析` 深挖 Top 标的 | 通常 1 个 |
| A 股市场复盘 | “今天A股怎么样 / 上证 / 创业板 / 科创板 / 北向 / AI 算力链 / 光模块” | `A股市场每日分析` | 可选 `个股深度分析` 深挖龙头 | 通常 1 个 |
| 单个标的深度 | “分析一下 XXX / XXX 能不能买 / 估值贵不贵 / 长期持有吗”且无仓位信息 | `个股深度分析` | 市场日报仅提供环境 | 1 个为主 |
| 持仓复盘 | 有截图、成本、数量、P&L、仓位比例、保证金 | `持仓分析` | 个股/市场 Skill 仅作背景 | 1 个为主 |
| 单笔期权处理 | “这个 spread 要不要止损 / Roll / DTE / 浮亏 X%” | `持仓分析` | `个股深度分析` 可补基本面方向 | 1-2 个 |
| 跨市场映射 | “昨夜美股影响今天A股吗 / 明天A股算力链怎么走” | `A股市场每日分析` | `美股市场每日分析` 提供海外前导信号 | 2 个 |
| 候选交易初筛 | “今天该买啥 / 哪些票值得深挖 / Top bullish” | 对应市场日报 | `个股深度分析` 深挖 1-3 只 | 1-2 个 |
| 财报后复盘 | “XXX 财报后怎么看 / 财报超预期还能买吗” | `个股深度分析` | 未来可接 `财报专项分析` | 1 个 |
| 港股 IPO / 打新 | “港股 IPO 值不值得打 / 打新 / 中签率 / 超购 / 暗盘 / 招股 / 首日溢价” | `港股IPO投资分析` | `个股深度分析`（仅价值视角补充） / 市场环境 | 1 个 |
| 组合优化 | “账户健康吗 / 如何调仓 / 风险集中吗” | `持仓分析` | 美股/A股市场日报提供宏观背景 | 1-2 个 |

### 3.2 优先级裁决规则

当同一句话命中多个路径时，按以下优先级裁决：

| 优先级 | 裁决条件 | 主 Skill |
|---|---|---|
| P0 | 有持仓截图、成本、数量、浮盈亏、期权腿、保证金、Roll/止损/止盈 | `持仓分析` |
| P1 | 明确问市场、大盘、指数、板块、盘前/盘中/盘后 | 对应市场日报 |
| P2 | 单个标的，无仓位上下文，问估值/商业模式/长期价值/买卖 | `个股深度分析` |
| P3 | 跨市场问题，且落地交易市场明确 | 落地市场对应日报 |
| P4 | 未来新增专项，如港股 IPO、财报、期权筛选 | 对应专项 Skill |

### 3.3 单 Skill 优先规则

默认只触发一个主 Skill，除非满足以下任一条件：

1. **跨市场映射**：例如美股前导 → A 股开盘。
2. **持仓决策依赖基本面重估**：例如用户持有某票大亏，且问是否长期拿。
3. **市场日报筛出候选标的后用户要求深挖**：例如“今天半导体最强的是谁，挑 1 只展开”。
4. **期权策略需要标的方向确认**：持仓分析处理合约，个股分析补充基本面方向。
5. **IPO/财报专项尚未独立成 Skill**：临时由个股分析 + 市场环境协同。

## 四、子 Skill 路径定义

### 4.1 美股市场每日分析

| 字段 | 定义 |
|---|---|
| 主路径 | `美股市场每日分析` |
| 适用 | 美股大盘、宏观、VIX/VVIX、利率、美元、板块轮动、Mag7、半导体、AI 软件 |
| 不适用 | 单股估值深度、持仓止损、具体期权 Roll |
| 协同 | 可把 Top Bullish/Top Bearish 交给 `个股深度分析` |

触发示例：
- “今天美股怎么样”
- “纳指盘前怎么看”
- “VIX 是不是要爆”
- “半导体今天强不强”

### 4.2 A 股市场每日分析

| 字段 | 定义 |
|---|---|
| 主路径 | `A股市场每日分析` |
| 适用 | A 股指数、北向/两融、政策、主线板块、AI 算力链、BOM 自嗨审计、跨市场映射 |
| 不适用 | 单股估值深度、持仓调仓、港股 IPO |
| 协同 | 引用 `美股市场每日分析` 的海外前导信号；单股深挖交给 `个股深度分析` |

触发示例：
- “今天 A 股怎么样”
- “创业板/科创 50 怎么看”
- “明天 A 股算力链怎么走”
- “光模块板块今天是不是过热”

### 4.3 个股深度分析

| 字段 | 定义 |
|---|---|
| 主路径 | `个股深度分析` |
| 适用 | 单标的商业模式、护城河、财务、估值、情绪、技术、期权策略 |
| 不适用 | 有持仓成本/P&L 的操作问题、全市场复盘 |
| 协同 | 美股标的引用美股市场环境；A 股标的引用 A 股 BOM 审计和交易制度 |

触发示例：
- “分析一下 NVDA”
- “MU 现在能不能买”
- “中际旭创估值贵不贵”
- “GOOGL 是否值得长期持有”

## 七、反例与纠偏规则

### 7.1 错误路由反例

| 用户问题 | 错误路由 | 正确路由 |
|---|---|---|
| “我持有 NVDA，成本 $X，要不要卖” | 个股深度分析 | 持仓分析 |
| “今天美股怎么样” | 个股深度分析 | 美股市场每日分析 |
| “中际旭创是不是国产自嗨” | A股市场日报完整复盘 | 个股深度分析 + A股 BOM 审计 |
| “ARM bear call spread 亏 95%，怎么办” | 个股深度分析 | 持仓分析 |
| “明天 A 股算力链怎么走” | 个股深度分析 | A股市场每日分析 + 美股前导 |

### 7.2 叙事漂移纠偏

当用户指出前后判断不一致时：

1. 立即回到本 Skill 公共 Hard Rules。
2. 重新拉实时数据。
3. 明确区分：基本面变化 / 技术面变化 / 市场环境变化 / 前次判断错误。
4. 不得为了维护前次结论而选择性使用数据。
5. 输出“修正后结论 + 哪条规则触发了修正”。

### 7.3 数据缺失纠偏

当关键数据缺失时：

1. 不输出强交易建议。
2. 输出“缺失数据清单”。
3. 输出“恢复数据后需要重新跑的子路径”。
4. 若用户要求先给框架，只能输出条件化 if-then 方案。

```markdown
description: "作为投资分析中枢的子路径，处理 XXX 场景。仅当中枢路由到本 Skill 或用户明确要求时调用。"
```

### 8.X 跨 Skill 引用路径契约（强制）

为保证 Skill 互引在内容/行号变化、跨用户机器、跨 IDE 渲染时持续可用，**所有 Skill 之间的相互引用必须遵守以下契约**：

1. **必须使用相对路径**：以当前 SKILL.md 所在目录为基准，形如 `../<sibling-skill>/SKILL.md`。
   - ✅ `[投资分析中枢 §3](../investment-router/SKILL.md)`
   - ❌ `[投资分析中枢 §3](file:///Users/.../investment-router/SKILL.md)`（绝对路径，跨机器失效）
2. **禁止使用 `#L<num>` 行号锚**：行号在内容编辑时极易漂移。
   - ✅ `[投资分析中枢 §2](../investment-router/SKILL.md)` + 文本中显式写明 `§2.4 / §2.5` 章节号
   - ❌ `[投资分析中枢 §2](../investment-router/SKILL.md#L56-L137)`
3. **章节号即引用契约**：被引用方必须维持稳定的 `§X` / `§X.Y` 编号；删除或重排章节时必须 grep 全项目同步更新引用文本。
4. **重命名 / 移动 Skill 时的清理动作**：
   ```bash
   # 改名 / 移动 / 删除前，先全局检索受影响的引用
   grep -rn "\.\./<old-skill-name>/SKILL\.md" .trae/skills/
   # 然后批量替换为新路径或在引用方决定降级处理
   ```
5. **新建 Skill 入仓时的体检**：必须确认 `grep -rn "file:///"` 与 `grep -rnE "SKILL\.md#L[0-9]+"` 在 `.trae/skills/` 下均返回空集，否则视为入仓不合格。
6. **可选锚点（B 方案）**：若未来希望支持点击直跳，可在被引用章节标题前加 HTML 锚点 `<a id="public-rules"></a>`，引用方写 `(../investment-router/SKILL.md#public-rules)`；但锚点 ID 一旦定义就视为契约的一部分，禁止随意改名。
